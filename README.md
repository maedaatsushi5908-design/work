## `ev` — 期待値ベースの投資プロセス

### 何を解くのか

「期待値の高い株は存在する」は正しい。問題は別のところにある。

> **自分がそれを事前に識別できたことを、どうやって確認するのか。**

年率アルファ3%・トラッキングエラー15%なら、t値が2に達するまで **100年** かかる。

```
years = (t · TE / α)² = (2 × 0.15 / 0.03)² = 100
```

**リターンで自分の実力を検証することは、人生の長さでは不可能。** 競馬なら
1シーズンで数千回の独立試行が得られるが、株は違う。この非対称性が、競馬の
期待値思考をそのまま株に持ち込めない理由である。

`ev` は2点でこれに対処する。

1. **エッジの源泉を運ではなく構造に置く。** 大口資金が物理的に入れない領域を
   選ぶ。事前に観測できる客観的事実なのでバイアスが入らない
2. **実力の測定器をリターンからキャリブレーションに替える。** 確率予測の
   当て具合は年20〜30件でも傾向が見える。リターンより桁違いに速く測れる

詳細は **[docs/METHOD.md](docs/METHOD.md)** を参照。

### インストール

**不要。** Python 3.9以上の標準ライブラリのみで動く。`pip install` は要らない。
numpy も pandas も使わない。

```bash
python3 -m ev.cli demo      # まずこれを実行する
```

### 6つの工程

```
0. 既存の成績を疑う          ev diagnose     試行数と選抜バイアスを控除する
1. 構造的ユニバース選別      ev screen       大口が入れない帯域を成績を見ずに絞る
2. ベースレートを置く        ev.base_rates   物語より先に頻度
3. 買う前に確率を書く        ev forecast     反証可能・期限付き・改変不能な台帳へ
4. キャリブレーションを測る  ev calibration  ここが実力の測定器
5. 実績でゲートしたサイジング ev size         証明されていないエッジには賭けない
```

### 使用例

```bash
# サイジングの直観: 期待値がプラスでも資産が減る
python3 -m ev.cli bet --win 0.5 --loss -0.4 --p 0.5

# アルファ検証に必要な年数
python3 -m ev.cli years --alpha 0.03 --te 0.15

# 既存バックテストの診断
python3 -m ev.cli diagnose --sharpe 0.88 --n-obs 2470 --trials 54 \
    --candidates 4000 --selected 116

# 構造的ユニバース選別
python3 -m ev.cli screen --csv examples/universe_example.csv --portfolio 10000000

# 予測 → 結果記録 → 評価 → サイジング
python3 -m ev.cli forecast    --journal j.db --file examples/forecast_example.json
python3 -m ev.cli resolve     --journal j.db --id FC00001 --claim c1 --outcome true
python3 -m ev.cli journal     --journal j.db
python3 -m ev.cli calibration --journal j.db
python3 -m ev.cli size        --journal j.db --id FC00001 --adv 10000000
```

### モジュール構成

| モジュール | 役割 |
|---|---|
| `ev.validation` | Deflated Sharpe、PBO、多重検定ハーカット、ウォークフォワード、選抜バイアス |
| `ev.universe` | 構造的選別（機関排除度・カバレッジ・出口確保） |
| `ev.base_rates` | 経験的ベースレート（経験ベイズ縮小、Wilson区間） |
| `ev.forecast` | 反証可能な確率予測の記録と解決 |
| `ev.ledger` | 追記専用・ハッシュチェーン付き台帳（改変検知） |
| `ev.calibration` | Brierスコア、Murphy分解、BSS、較正傾き、再較正 |
| `ev.sizing` | 厳密ケリー、ベイズ縮小、実績ゲート、流動性キャップ |
| `ev.performance` | アルファのt値、必要年数、ボラティリティ・ドラッグ |
| `ev.stats` | 数値基盤（正規分布、Student-t、不完全ベータ、ブートストラップ） |

## 新高値ブレイク戦略バックテスト（既存）

> **注意:** 申告されている成績（総リターン301%、シャープ0.88）は、真のエッジが
> 0でも再現できる水準である。銘柄ユニバースがバックテスト期間の成績で選抜されて
> おり（`config.py:50`）、これだけで年率+23%相当の見かけのエッジが生じる。
> 詳細と対策は **[docs/DIAGNOSIS.md](docs/DIAGNOSIS.md)**。

### 戦略ルール

| ルール | 内容 |
|--------|------|
| エントリー条件 | 終値がN営業日間（既定195日）の新高値を更新 |
| 出来高条件 | 前日比で出来高が増加していること |
| エントリー価格 | シグナル翌日の始値 |
| 損切り | エントリー価格から -10% |
| トレーリングストップ | 保有中の最高値から -20% |
| 最大保有銘柄数 | 5銘柄（均等分散） |

### 実行方法

```bash
pip install -r requirements.txt     # yfinance / pandas / matplotlib が必要
python main.py                      # バックテスト
python main.py --show               # グラフを画面表示
python scanner.py --notify          # 毎朝のスキャン＋Discord通知
```

主なオプション:

| オプション | デフォルト | 説明 |
|------------|-----------|------|
| `--start` / `--end` | 2015-01-01 / 2024-12-31 | バックテスト期間 |
| `--capital` | 1,000,000 | 初期資金（円） |
| `--high-period` | 195 | 新高値判定期間（営業日） |
| `--stop-loss` | -0.10 | 損切りライン |
| `--trailing` | -0.20 | トレーリングストップ |
| `--max-pos` | 5 | 最大保有銘柄数 |
| `--tickers` | - | 対象ティッカーを空白区切りで指定 |

出力は `output/` に生成される（資産推移グラフ、取引分布、月次リターン、`trade_log.csv`）。
毎朝の自動化と引き継ぎ事項は [HANDOFF.md](HANDOFF.md) に記載。

## 注意事項

- `ev` は儲かることを保証しない。保証するのは**自分を騙さないこと**だけである
- キャリブレーションが良いことはリターンが良いことを意味しない
- 構造的に大口が入れない領域に歪みがあるとは限らない。低流動性それ自体が
  リスクの対価である可能性は常に残る
- これらは教育・研究目的のツールであり、投資助言ではない
- 過去のパフォーマンスは将来を保証しない
