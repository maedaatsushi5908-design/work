## 2. 最大の発見: 総括表は手入力

各集計シートの「数式 vs 直接入力の数値」を測定した結果:

| シート | 数式 | 直接入力の数値 | 手入力率 |
|---|---:|---:|---:|
| **`01_soukatsu` 総括表（管工事）** | **19** | **271** | **93.4%** |
| `06_hosou_shukei` 舗装集計 | 35 | 109 | 75.7% |
| `06_dokou_hosou` 管工（土量集計 | 119 | 106 | 47.1% |
| `05-1` 延長集計表 採用(伏越削除) | 451 | 260 | 36.6% |
| `06_dokou_hosou` 舗装（集計） | 2176 | 638 | 22.7% |
| `06_dokou_hosou` 総括表（舗装工事） | 742 | 163 | 18.0% |
| `06_dokou_hosou` 総括表（土工事） | 912 | 106 | 10.4% |

`06_dokou_hosou.xlsx` の内部集計は数式で連動済み（手入力率10〜23%）だが、
**`01_soukatsu.xlsx` の総括表は外部リンクを一切持たず、271個の数量がすべて直接入力**。
つまり 02〜08 の各計算書の結果を、人が目で読んで総括表に打ち込んでいる。

## 3. 総括表（管工事）のセル構造

3ブロック構成。各ブロックは左右2列組。

| ブロック | 見出し行 | データ行 |
|---|---:|---|
| 数量総括表（管工事-1） | 6 | 7〜65 |
| 数量総括表（管工事-2） | 71 | 72〜124 |
| 数量総括表（管工事-3） | 136 | 137〜194 |

列の割り当て（3ブロック共通）:

| 列 | 内容 |
|---|---|
| B | 名称（左） 例: 鋳鉄管据付、鋼管撤去、仕切弁据付 |
| C | 摘要（左） 口径 75〜900 の数値 |
| **D** | **管工事＝数量（左）← 転記先** |
| E | 備考（左） |
| F | 名称（右） |
| G | 摘要（右） 口径 |
| **J** | **管工事＝数量（右）← 転記先** |
| K | 備考（右） |

その他:
- `B5 = 表紙!C2`（工事名）、`B70 = B5`、`B135 = B70` でブロック間に伝播
- `J111〜J115`, `J124` に `=ROUNDUP(D44/6,0)` 形式の換算式（6m割）
- `K173:K178` の `VLOOKUP(...,$O$173:$R$204,...)` は**参照先テーブルが空**で常に "" を返す。使われていない残骸。

## 4. 雛形複製パターン

手作業が多いもう一つの箇所。同一構造のシートを口径・種別ごとにコピーして使っている。

- `03_kirikan.xlsx`: 114行×29列・結合220箇所の雛形が18シート
  （`白紙(4m)` `白紙(5m)` `白紙(6m)` が未使用の雛形として残っている）
- `06_dokou_hosou.xlsx`: `試掘（舗/土` × 50/75/300/400/600、`管工（舗` `管工（土量1/2）` × 50/75/200/400/600
- `07_futaikou.xls`: 39行×53列の構造物撤去・設置シートが構造物種別ごとに複製

非表示シートが多数あり（`06_dokou_hosou` で12シート、`03_kirikan` で2シート）、
使用しない口径を隠して運用していると見られる。

## 5. 技術的な注意点

- `.xls`（97-2003形式）が4ファイル: `02` `04` `07` `08`。VBAで扱う分には問題ないが、
  Python側の解析では xlrd / LibreOffice が必要（openpyxl は非対応）。
- シート保護・ブック保護は全ファイルで未設定。
- 外部ファイルへのリンクは総括表には無い。
- VBAを組み込む場合は `.xlsm` として保存し直す必要がある。
