# M_Hasai － 総括表（土工事）への転記

マクロは1本だけ。

```
総括表の数量を転記する()
```

いまのところ2つの工種を扱う。**転記元の並び方が違うので、入れる式も違う。**

| 工種 | 総括表 | 入れる式 | なぜ |
|---|---|---|---|
| 舗装版破砕工 | 13〜67行 | `=SUMIF(…)` | 転記元の厚さが詰めて並ぶ |
| 舗装切断工 | 9〜12行 | `='試掘（舗50'!P5` | 厚さ区分が固定の文字で動かない |
| 殻運搬（現場→仮置場） | 77〜81行 | `=給水2度!AA10` | 摘要で1対1に決まる |
| 殻運搬（現場→処分地） | 82〜95行 | `=給水2度!AA28` | 〃 |
| 殻運搬（積込み） | 96〜98行 | `=給水2度!AA25` | 〃 |

```
舗装版破砕工
=SUMIF('試掘（舗50'!$O$11:$O$17,'総括表（土工事）'!$I14,'試掘（舗50'!$P$11:$P$17)
        └ 転記元の舗装厚欄      └ 総括表の厚さ欄      └ 転記元の合計欄

舗装切断工
='試掘（舗50'!P5
```

工種を増やすときは、マクロ先頭の定数に総括表の工種名と転記元のブロック
見出しを足し、`WriteAll` の振り分けに1行足す。

## 転記元の並びは3種類ある

同じ「舗装版破砕」でも、シートによって欄の並びが違う。マクロは見出しを
手がかりに**枠（種別・厚さ列・合計列・合計の幅）の一覧**を作り、
総括表の行の種別に合う枠だけを足す。

### その1　種別・舗装厚 ／ 合 計 が並ぶ形（試掘・管工・仮配・給水付替）

```
□舗装版破砕工（人力）
種別・舗装厚 | 合 計  ‖ 種別・舗装厚 | 合 計
As    4      |  0.6   ‖ Co    15     |  0.3
```

「種別・舗装厚」の1つ右が厚さ、その右で最初に来る「合 計」が数量。
枠は左から As、Co。`仮配（舗` のように Co の枠が無いシートもある。

### その2　車道／歩道 の号工が並ぶ形（給水2度）

```
□舗装版取壊工 及び 仮復旧工
車道　5号工（K:N 結合）  ‖ 歩道　5号工（O:R 結合）
K=舗装厚 | L:N=数量      ‖ O=舗装厚 | P:R=数量
```

結合の左端が厚さ、その次から右端までが数量。**どちらの枠も As**
（29行目が `As車道`、33行目が `As歩道`）なので、総括表では2枠を足す。

```
=SUMIF(給水2度!$K$4:$K$6,'総括表（土工事）'!$I31,給水2度!$L$4:$N$6)
+SUMIF(給水2度!$O$4:$O$6,'総括表（土工事）'!$I31,給水2度!$P$4:$R$6)
```

Co の枠が無いので、**Co だけの行（67行）には入れない**。

合計側の範囲が `$L$4:$N$6` と3列あるのは、転記元の合計セルが L:N で
結合されているため。SUMIF は条件範囲と同じ形の分しか見ないので、
広くても結果は変わらない。同じ理由で `仮配（舗` は `$W$10:$X$17`、
`給水(舗` は `$T$10:$U$16` と2列になる（結合が2列のため）。

### その3　舗装切断工（固定の区分）

下の節を参照。

### その4　「＝」で書かれたブロック（給水2度）

```
□As殻Co殻運搬（現場～仮置場）
  As車道 （ 0 ）        ＝  0     ← 10行
  As歩道 （ 0 ）        ＝  0     ← 12行
□掘削  ●床 堀
  砂質土（人力）（0）-（0） ＝  0     ← 16行
□As殻Co殻運搬処理（現場～処分地）  ●仮置土積込工
  As （ 0 ）           ＝  0     ← 25行
●殻運搬処理
  As車道 （ 0 ）        ＝  0     ← 28行
  As歩道 （ 0 ）        ＝  0     ← 30行
```

**「＝」の右が数量**、そこから左へ戻って最初に出てくる文字が摘要
（かっこ・ハイフン・数式・数値は飛ばす。左端から探すと行見出しを拾う）。
ブロックは次の `□` か `●` が出たところで打ち切る。

総括表の行は、工種名と副見出しで転記元のブロックを選ぶ。

```vba
Private Const KARA_MAP As String = _
    "殻運搬>現場+仮置場>□As殻Co殻運搬（|" & _
    "殻運搬>現場+処分地>●殻運搬処理|" & _
    "殻運搬>積込み>●仮置土積込工"
```

「殻運搬」は行き先で分かれるので工種名だけでは決まらない。
`～` は文字コードが揺れるので使わず、両端の語で照合する。
`仮置場→処分地`（99〜102行）は転記元が無いので入れていない。

摘要の照合は3段。

1. そのまま一致（`As・車道` → `As車道`。`・` は落とす）
2. ラベルが摘要の頭に一致（`As（仮置土）` → `As`）
3. 摘要に As / Co が無い行（`舗装版破砕` など）は種別で分かれて
   いないということなので、ブロックの**先頭行**を採る

総括表では同じ摘要が複数行（人力／15㎝以下×2／15㎝超）に分かれているが、
**転記元は摘要ごとに1つしか数量が無い**。
どの行に入れるかは**塗り分けが決めている**（O列は 77・83・87・91・96・97 行）。

### 殻運搬の欄は黄色ではない

77〜81・96〜97・99〜101行は、黄色ではなく**薄い橙**（テーマ色の
アクセント6）で塗ってある。凡例には出ていないが、黄色と同じく
「ここに値が入る」という指定なので、この区間だけ薄橙も入力セルとして扱う
（`IsSubCell`）。この工事では8行65セルにしか現れない。

```
82 As・車道 人力      黄=JKLMN     ← 試掘の列
83 As・車道 15㎝以下   黄=OPQRS     ← ここに 給水2度!AA28
86 As・歩道 人力      黄=JKLMN
87 As・歩道 15㎝以下   黄=OPQRS     ← ここに 給水2度!AA30
```

`●殻運搬処理` を持たない転記元（試掘・管工など）は、この工種がまだ
未対応というだけなので**黙って飛ばす**（見送りには数えない）。
どのシートで見つかったかは確認画面に出る。

## 舗装切断工はなぜ直接参照でよいのか

転記元の厚さ区分は `t≦15` `15<t≦30` `30<t≦40` と**固定の文字**で並ぶ。
舗装版破砕のように工事によって詰めて動くことがないので、行がずれない。

```
試掘（舗50 の □舗装切断工
  行3   種別・舗装厚 | 合 計  ‖ 種別・舗装厚 | 合 計
  行4   As  t≦15     |  3.60  ‖ Co  t≦15     |  0
  行5   As  15<t≦30  |  0     ‖ Co  15<t≦30  |  0
  行6   As  30<t≦40  |  0     ‖ （Co は無し）
```

ただし**ブロックの位置はシートによって違う**（試掘は4行目から、管工は10行目から）
ので、行は固定しない。マクロを流すたびに区分を照合して決め直す。

総括表は `t≦15㎝`、転記元は `t≦15` と ㎝ の有無が違うので、
㎝（U+339D）を落として突き合わせる。

## なぜ SUMIF なのか

転記元の舗装厚は、その工事に出てくる厚さだけが**詰めて並ぶ**。

```
試掘（舗50 の □舗装版破砕工
  行11  As  4cm   0.0
  行12  As  10cm  1.2      ← 5cm が無いので 10cm が2行目に来る
```

`='試掘（舗50'!P12` のように行を固定していると、別の厚さの数量を拾う。
総括表の厚さ欄（I列）と一致する行だけを合計すれば間違えない。

転記元の厚さ欄は `INDEX/MATCH` で毎回組み替わるので、
**目で見ても行がずれていることに気づけない。** そこが危ないところ。

## やっていること

1. 総括表の、いちばん左の工種名で行を仕分ける
   （「舗装版破砕」= 13〜67行、「舗装切断工」= 9〜12行）
2. **舗装厚の列**を決める。区間の行で数値が現れた回数がいちばん多い列（I列）
3. 各行の**種別**（工種名より左にある As / Co の字）を読む
4. 下の対応表にある列のうち、**黄色く塗ってあるセル**にだけ数式を入れる
5. As の行は転記元の As 側、Co の行は Co 側、As・Co の行は両方を足す

舗装版破砕は厚さ列が**数値**の行だけを見る。「計」などの文字がある行
（合計欄）は触らない。**空欄の行には入れる** — 16行目のような予備の行に
後から厚さを入れたとき、そのまま数量が出るようにするため。
SUMIF は空欄に当たらないので 0 のまま。

舗装切断工は逆で、厚さ列が**区分の文字**（`t≦15㎝`）の行を見る。

黄色は「入力セル（各数量計算書の数量を転記間違いないように！）」という
総括表の凡例そのままで、**どこに値が入るかは作成者が塗り分けている**。
推測せずにそれに従う。行26以降は口径ごとに別ブロックへ分かれるが、
塗り分けがそのまま境界になっている。

## 工事が変わったら直すところ

**マクロは総括表と転記元が同じブックにあることを前提にしている。**
東白川の `06 土工事・舗装復旧 数量計算書` がその形。
別ブックにまたがる工事（長田）は下の「他の工事から分かったこと」を参照。

まず、その工事の一式を `excel/works/<名前>/` に入れて次を流す。

```
python3 excel/docs/scan_work.py excel/works/02_nagata
```

フォルダ内の全ブックを見て、総括表と転記元が別ブックでも突き合わせる。

総括表の見出し・シート名・舗装版破砕ブロックを突き合わせて、
下の2つの下書きを出す。候補が1つに絞れない列には `★` が付く。
1件目の工事で流すと、手で確かめた `COL_MAP` と完全に一致する。

マクロの先頭にはこれだけ置いてある。

```vba
Private Const TARGET_SHEET As String = "総括表（土工事）"

Private Const COL_MAP As String = _
    "J=試掘（舗50|" & _
    "K=試掘（舗300|" & _
    ...
    "U=管工（舗600"
```

見出しの口径（`PE50-300`）とシート名の数字は1対1で対応しないので、
**マクロには推測させず、決めた結果を書いておく**。使わない列は書かなくてよい。

**シート名の数字は口径ではない。** `管工（舗50` の「50」は様式の枠の名前で、
「(75-300)新設」という見出しでも転記元は `管工（舗50` になる。
詳しくは下の「他の工事から分かったこと」を見ること。

`scan_work.py` の決め方は2段構え。

1. **同じ系統の列数と転記元シート数が同じなら、並び順どおりに組む**
   （枠の意味が順番で決まっているため。長田の管工事 5列 ⇔ 5枚）
2. 数が合わないときは、候補の少ない列から順に決めて使ったシートを外す
   （東白川の管工事 4列 ⇔ 5枚。`S(75-300)` が先に `管工（舗75` に決まる）

両方の工事で、手で確かめた `COL_MAP` と一致することを確認済み。
`給水2度` は舗装版破砕のブロックが無いので入れていない。

対応表は実行前の確認画面にそのまま出る。ブロックが見つかったかどうかも
一緒に出るので、貼り間違いはそこで気づける。

```
 J列 → 試掘（舗50    (11-17行 As=O/P Co=R/S)
 P列 → 仮配（舗      (10-17行 As=R/W Coなし)
 R列 → 管工（舗50    (16-23行 As=R/T Co=V/X)
```

転記元の**ブロックの位置は自動で探す**。「□舗装版破砕」を見つけ、その下の
「種別・舗装厚」と「合 計」の並びから列を決め、As / Co が続く行数を数える。
シートごとに列が違う（試掘は O/P、管工は R/T）ので、ここは固定できない。

行の終わりに**予備を1行足す**。次の工事で舗装厚が1種類増えても式を直さずに
済む。SUMIF は空欄に当たらないので、余分に含めても結果は変わらない。

## 入れたのに空欄に見える件

**総括表は「ゼロ値のセルにゼロを表示する」がオフ**になっている
（`showZeros = False`）。数式を入れても、結果が 0 のセルは画面上は
まったくの空欄に見える。この工事では102個中85個が 0 なので、
ぱっと見では何も入っていないように見える。

入ったかどうかは次のどれかで確かめる。

- マクロが作る **「転記結果」シート**（セル・厚さ・種別・転記元・
  前の値・後の値・入れた式の一覧。値が変わった行は色を付ける）
- セルをクリックして**数式バー**を見る
- <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>@</kbd> で数式表示に切り替える

「転記結果」シートは要らなければ消してよい。

## 他の工事から分かったこと（参照用）

`excel/works/02_nagata/` に **長田(花山町2丁目他)配水管取替工事** の一式を
置いてある。マクロはまだこの工事向けではないが、様式の読み方を確かめる
材料として使える。分かったことは3つ。

### 1. シート名の数字は口径ではない

`管工（舗50` の「50」は**様式の枠の名前**。どの区分を読んでいるかは、
そのシートが 延長表 のどこを参照しているかで決まる。**両方の工事で同じ。**

| 枠 | 延長表の区分 | 東白川の列 | 長田の列 |
|---|---|---|---|
| 1枠目 `（舗50` | ■新設部 | R (PE50-300)新設 | R (75-300)新設 |
| 2枠目 `（舗200` | — | （列なし） | S (200-300)新設 |
| 3枠目 `（舗75` | ■一般部・■撤去部 | S (75-300)取替・撤去 | T (75-300)取替・撤去 |
| 4枠目 `（舗400` | — | T (400-500) | U (400-500) |
| 5枠目 `（舗600` | — | U (600以上) | V (600以上) |

長田の `R（75-300)新設` に「50」の文字は無いが、転記元は `管工（舗50`。
**見出しの数字だけで決めると、新設と取替・撤去を取り違える。**

### 2. 口径で分かれない系統のシート名は変わらない

| 系統 | シート名 | 備考 |
|---|---|---|
| 仮配管 | `仮配（舗` | 両方の工事で同じ。**Co 側の欄が無い**（As だけ合計する） |
| 給水付替 | `給水(舗` | 両方で同じ。`(` は**半角**（`給水（舗` ではない） |
| 給水2度 | `給水2度` | 見出しが `□舗装版取壊工`、並びも車道／歩道の2枠。**As のみ** |

### 3. 工事によって総括表の置き場所と列数が変わる

| | 東白川 | 長田 |
|---|---|---|

## 検証について

- `excel/docs/verify_hasai.py` … **マクロと同じ判定を Python に写したもの**
  102セル分の数式を出し、J14 が指示どおりの文字列かを確かめる
- `excel/docs/scan_work.py` … 工事フォルダから `COL_MAP` の下書きを作る
- `excel/docs/lint_vba.py` … 名前と構文の機械チェック
  - 予約語を変数名に使っていないか（`Dim any As Boolean` は構文エラー）
  - **手続き名と同じ名前の変数**（`Function LastRow()` と `Dim lastRow` は
    VBA が大文字小文字を区別しないため衝突する）
  - VBA / Excel の関数と同じ名前の変数（`Dim Val As String` など）
  - **モジュール内の手続きを、引数の数を間違えて呼んでいないか**
    （引数を1つ増やしたのに古い呼び出しが残っている、など）
  - **関数の戻り値への直接添字**（`Split(s, "|")(1)`。要素が足りないと
    実行時に落ちる。VBA の `And` は左が偽でも右を評価するので、
    `If n = 2 And Split(s,"|")(1) = …` では守れない）
  - モジュールレベルの宣言が手続きより後ろに来ていないか
  - Sub / Function と End の対応、コード行の全角スペース
