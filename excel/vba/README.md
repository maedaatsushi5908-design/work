# 総括表 自動転記・照合マクロ

`01 総括表` の数量を、`02`〜`08` の各数量計算書から自動で拾って入れる。
入れる前に必ず差分を見せ、書き込む前に総括表のバックアップを取る。

## ファイル構成

保守用の小さいモジュールと、貼り付け用の1ファイルを分けている。

```
excel/vba/src/          保守用。ここを直す
  M_Util.bas              文字列正規化・セル操作の共通処理
  M_Link.bas              06 用。シート間リンクの数式化
  M_Config.bas            01 用。転記定義シート
  M_Engine.bas            01 用。転記元セルの解決
  M_Main.bas              01 用。照合・転記の入口

excel/vba/dist/         貼り付け用。src から生成する
  M_Link.bas              06 に貼る1ファイル（M_Util + M_Link）
  M_Tenki.bas             01 に貼る1ファイル（M_Util + M_Config + M_Engine + M_Main）
  sjis/                   同じものの Shift-JIS 版（インポート用）
```

**貼り付けるのは `dist/` の方。ブックごとに1ファイルで済む。**
`src/` を直したら `python3 excel/docs/build_vba.py` で作り直す。

同じ関数を2箇所で直す羽目にならないよう、共通部分は `src/M_Util.bas` に
1つだけ置き、生成時に両方へ取り込んでいる。

生成時にやっていること:

- `Attribute VB_Name` と `Option Explicit` を1つに畳む
- **`Type` `Const` `Enum` などのモジュールレベル宣言を、すべて先頭に集める**
  VBA はこれらを全ての手続きより前に置かないとコンパイルできない。
  単純に連結すると2つ目以降の宣言が手続きの後ろに来て構文エラーになる
- モジュールをまたぐために `Public` にしてある `InitSources` などを
  `Private` に変換する（`Public` のままだと Alt+F8 の一覧に出てしまう）

宣言の位置は `lint_vba.py` でも検査している。

## 01 総括表 用（M_Tenki）

| マクロ名 | 動き |
|---|---|
| `定義シートを作成` | 転記のルールを書いた「転記定義」シートを作る。**最初に一度だけ** |
| `照合実行` | **書き換えない。** 総括表の値と計算値を突き合わせ、一覧を出す |
| `転記実行` | 差分を見せて確認を取り、OKならバックアップを作ってから書き込む |

総括表の数量40項目のうち、**26項目が自動転記の対象**。残り14項目（仕切弁・
空気弁・フランジ継手など）は図面から数える手入力項目なので、照合結果に
「手入力」として現在値だけ表示する。

# シート間リンクの数式化（M_Link）

`06 土工事・舗装復旧` の **総括表（土工事）** は、試掘シート・管工シートから
値を1本ずつ手でリンクしている（85本）。これを数式に置き換える。

## マクロは1本だけ

```
総括表の数式を作り直す
```

中でやること:

1. 今あるリンクを読み取って「リンク設定」シートを作る
   （前回の設定があれば、口径などの手直しは引き継ぐ）
2. 何をするかを表示して確認を取る
3. バックアップシートを作ってから数式を書き込む
4. **値が変わったセルを一覧にして表示**し、納得できなければその場で元に戻す

確認も点検も取り消しも、この1本の中に入っている。
`dist/M_Link.bas` を標準モジュールに貼り付けて使う。これ1つで動く。

## 2種類の数式

取り込み時にどちらを使うか自動で割り当てる。設定シートの「方式」欄で変更できる。

### 直接（並びが固定の箇所）

```
='試掘（舗400'!P4
```

舗装切断工のように、転記元の行が `t≦15` `15<t≦30` `30<t≦40` と固定文字で
並ぶ箇所。セルの位置が動かないので直接参照でよい。この工事では69箇所。

### 条件式（舗装厚で照合する箇所）

```
=SUMIF('試掘（舗50'!$O$11:$O$17,'総括表（土工事）'!$I14,'試掘（舗50'!$P$11:$P$17)
        └ 転記元の舗装厚      └ 総括表の厚さ欄      └ 転記元の合計
```

種別が `As ・ Co` の行は As 側と Co 側を足す。

```
=SUMIF('管工（舗75'!$R$16:$R$23,'総括表（土工事）'!$I57,'管工（舗75'!$T$16:$T$23)
+SUMIF('管工（舗75'!$V$16:$V$23,'総括表（土工事）'!$I57,'管工（舗75'!$X$16:$X$23)
```

範囲はブロック（11〜16行）に**予備を1行足す**。次の工事で舗装厚が
1種類増えても式を直さずに済む。SUMIF は空欄に当たらないので、
余分に含めても結果は変わらない。

**舗装版破砕工のブロックは危険。** 転記元の舗装厚は、その工事で実際に出てくる
ものだけが詰めて並ぶ。

```
R16: =IF(MAX($E$389:$E$428)<ROW()-15,"",INDEX($D$389:$D$428,MATCH(ROW()-15,$E$389:$E$428,0),1))
```

実際に工事・口径で並びが違う。

| シート | R16 | R17 | R18 | R19 |
|---|---|---|---|---|
| `管工（舗50` | 4 | 5 | 10 | (空) |
| `管工（舗400` | 4 | 5 | 10 | **15** |
| `試掘（舗50` | 4 | **10** | (空) | (空) |
| `試掘（舗400` | 4 | 10 | 15 | (空) |

`試掘（舗50` には 5cm が無いので、`P12` は 10cm の数量になる。
固定セル参照では、5cm の行が 10cm の数量を拾ってしまう。

条件式なら、総括表の厚さ欄（I列）と一致する行だけを合計するので間違えない。
その厚さが転記元に無ければ 0 になる。種別が `As ・ Co` の行は両側を足す。

## ブロックの自動検出

転記元の列の並びは系統ごとに違うが、設定は要らない。見出しから探す。

1. `□舗装版破砕工` を含むセルを探す（数式なら計算結果で判定）
2. そのすぐ下で `種別・舗装厚` と `合 計` が並ぶ行を見つける
3. 各 `種別・舗装厚` の右にある最初の `合 計` を対にする。舗装厚列は種別列の隣
4. データ行は、種別列に `As` / `Co` が並ぶ範囲

| シート | ブロック行 | As(厚,合計) | Co(厚,合計) |
|---|---|---|---|
| `管工（舗xx` | 16〜22 | R, T | V, X |
| `試掘（舗xx` | 11〜16 | O, P | R, S |
| `給水(舗` | 10〜15 | R, T | W, Y |
| `仮配（舗` | 10〜16 | R, W | — |

## 展開の可否

| 区分 | 数 | 動き |
|---|---|---|
| 展開可 | 23群 | 同じ系統の全ての口径列に入れる |
| 展開不可 | 32群 | 今ある列だけに入れる |
| 対象外 | 3群 | 書き込まない |

**展開不可** は行ごとに口径が分かれている区間（行31-33がR列、行36,38がS列、
行41-43がT列）。同じ参照セルを複数の行が分け合うかで判別する。一律に入れると
二重計上になる。

**対象外** は `管工（土量1）` の行213・216・217。口径でシートの行数が違い、
列ごとに参照セルが異なる（S→AB13 / T→AB12）。1つのテンプレートでは書けない。

## リンク設定シートは残さない

毎回いまの数式から対応を読み直すので、設定シートを置いておく意味がない。
実行が問題なく終わったら**自動で消す**。

埋められなかった箇所があるときだけ、手がかりとして残す。
そのときは口径などを直してもう一度実行すれば反映される。

記録は「実行結果」シートに残る。

## 黄色い入力セルも埋める

総括表では、各計算書から値を写す場所が黄色く塗ってある。

```
J1 = 入力セル（各数量計算書の数量を転記間違いないように！）   ← 黄色
J2 = この表内でﾘﾝｸ入力されてるセル                        ← 薄緑
```

**黄色は「ここに値が入る」という作成者自身の指定**なので、推測せずに
そこだけを条件式で埋める。ブロックと列の対応も黄色の付き方がそのまま示している。

```
10cm以下      15cm以下
行26-30  →   行51-52   P列（仮配管）
行31-34  →   行54-55   O・Q・R列
行36-39  →   行57-58   S列（管工事75）
行41-44  →   行60-61   T列（管工事400）
行46-49  →   行63-65   U列（管工事600）
```

### 転記元シートの決め方

行によって同じ系統でも参照先が変わる（舗装版破砕は `舗` シート、土量は
`土` シート）ため、列だけでは決められない。2通りで解決する。

1. **口径のある系統**（試掘・管工事）
   行がいちばん近い同系統のリンクから接頭辞を借り、列の口径を足す。
   例: 行46 の U列 → 近くの 行43(T列) が `管工（舗400` → 接頭辞 `管工（舗`
   ＋ U列の口径 `600` → `管工（舗600`

2. **口径の無い系統**（仮配管・給水付替・給水2度）
   系統名でシートを直に探す。名前がそのまま一致するものを優先し、
   次に舗装版破砕のブロックを持つシートのうち括弧より前が一致するもの。

| 系統 | 転記元 | 決め方 |
|---|---|---|
| 給水2度 | `給水2度` | 名前が一致。ただし**破砕ブロックが無い**ので埋められない |
| 仮配管 | `仮配（舗` | 括弧より前で一致 |
| 給水付替 | `給水(舗` | 括弧より前で一致 |
| 試掘 | `試掘（舗xx` | 近くのリンク＋口径 |
| 管工事 | `管工（舗xx` | 近くのリンク＋口径 |

2文字だけで照合すると `給水2度` と `給水付替` が同じシートに当たるため、
括弧より前の全体で照合し、1つに絞れたときだけ採用する。

### 数式を入れるのは黄色いセルだけ

リンクを全口径列に広げるときも、書き込む先は**黄色い入力セルに限る**
（`YellowOnly`）。舗装版破砕は行26以降が口径ごとの別ブロックに分かれて
いて、系統の全列に機械的に広げると隣の口径の欄へはみ出すため。
もともとリンクのあった列は、塗り忘れていても残す。

**厚さ列（I）と種別列（E）は黄色いが転記先ではない。** ここは条件式の
照合材料なので、書き込むと循環参照になり厚さの値も消える。見出しに
系統名の無い列（G・AK・AT など）も同じ理由で触らない。

| 区分 | 数 |
|---|---|
| 書き込むセル | 206個（既存リンク 78 + 新規 128） |
| うち条件式（舗装厚で照合） | 91個 |
| うち直接参照 | 115個 |
| 埋められない | 8個（`給水2度` の7個＋`仮配（舗` の Co 1個） |

埋められなかったものは「実行結果」シートに理由つきで出る。
`仮配（舗` に Co 側の欄が無い行は、As だけを合計して注意書きを残す。

## INDIRECT について

一時は INDIRECT 形式も用意したが**外した**。数式バーで参照先が読めず、
参照元のトレースも `Ctrl`+`[` も効かない。利点は「マクロを再実行しなくてよい」
の一点だけで、口径を変えるのは工事の切り替え時だけなので割に合わない。

ただし**読み戻しには対応している**。以前 INDIRECT 形式にした総括表でも
そのまま実行できる（`Normalize` が普通の参照に読み替える）。

## 舗装版破砕（13〜25行）の展開

指示された式

```
=SUMIF('試掘（舗50'!$O$11:$O$17,'総括表（土工事）'!$I14,'試掘（舗50'!$P$11:$P$17)
```

を、同じ節のすべての行・すべての試掘列に広げる。13〜25行 × J〜N列で
**50セル**。厚さも種別も列も、式の中の参照だけが変わる。

| 行 | 厚さ | 種別 | J | K | L | M | N |
|---|---|---|---|---|---|---|---|
| 13 | 4 | As | ● | ● | ● | ● | ● |
| 14 | 5 | As | ● | ● | ● | ● | ● |
| 15 | 10 | As | ● | ● | ● | ● | ● |
| 18 | 14 | As | ● | ● | ● | ● | ● |
| 19 | 15 | As | ● | ● | ● | ● | ● |
| 21 | 20 | As | ● | ● | ● | ● | ● |
| 22 | 4 | Co | ● | ● | ● | ● | ● |
| 23 | 8 | Co | ● | ● | ● | ● | ● |
| 24 | 15 | Co | ● | ● | ● | ● | ● |
| 25 | 20 | Co | ● | ● | ● | ● | ● |

As の行は `O列（厚さ）／P列（合計）`、Co の行は `R列／S列` を見る。
列と転記元シートの対応は次のとおり。

| 列 | 見出し | 口径 | 転記元 |
|---|---|---|---|
| J | 試掘（PE50-300)新設 | 50 | `試掘（舗50` |
| K | 試掘（200-300）新設 | 300 | `試掘（舗300`（★口径は見出しからの推定） |

| M | 試掘（400-500） | 400 | `試掘（舗400` |
| N | 試掘（600以上） | 600 | `試掘（舗600`（★推定） |

★の3列は「リンク設定」シートで口径を直せる。

行14・行15 は元の固定参照（`P12`）を2行で分け合っていたため、以前は
「展開不可」として1列にしか入らなかった。条件式は舗装厚で照合するので
分け合っていても問題なく、**条件式の行は展開できる**ようにした。

## 見つかった不整合

`試掘（舗50` には 5cm が無く、`P12` は 10cm の数量（1.2）。
ところが総括表の **行14（I列=5）** がその `P12` を参照している。
本来 1.2 は **行15（I列=10）** に入るべき値。

計の行（17行目）で合算されるため総量は合っているが、厚さ別の内訳が
1段ずれている。舗装版破砕は厚さで単価が変わるので、要確認。

条件式にすると 行14 は 0 になり、行15 に 1.2 が入る。
実行後の「実行結果」シートに、この2セルが変更として出る。
