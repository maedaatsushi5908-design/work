# 期待値ベースの株式投資 — 方式

## 0. この方式が解こうとしている問題

「期待値の高い株は存在する」は正しい。銘柄間の期待リターンに差があることは
学術的にほぼ決着している（モメンタム、クオリティ、バリュー、低ボラティリティ）。

問題は別のところにある。

> **自分がそれを事前に識別できたことを、どうやって確認するのか。**

年率アルファ3%、トラッキングエラー15%だとしよう。t値が2に達するまでに必要な期間は

```
years = (t · TE / α)² = (2 × 0.15 / 0.03)² = 100年
```

集中投資してα=5%、TE=10%まで持っていっても16年。しかもその間に分布は
非定常に変化する。**リターンで自分の実力を検証することは、人生の長さでは不可能。**

競馬なら1シーズンで数千回の独立試行が得られ、その年に実力が判明する。株は違う。
この非対称性が、競馬の期待値思考をそのまま株に持ち込めない理由である。

この方式は次の2点でその問題に対処する。

1. **エッジの源泉を、運ではなく構造に置く。** 大口資金が物理的に入れない
   領域を選ぶ。これは事前に観測できる客観的事実であり、過去の成績を
   参照しないのでバイアスが入らない。
2. **実力の測定器をリターンからキャリブレーションに替える。** 確率予測の
   当て具合は、年20〜30件でも傾向が見える。リターンより桁違いに速く測れる。

## 2. 工程0 — 既存の成績を疑う

### なぜ最初にこれをやるのか

バックテストの数字は、ほぼ例外なく2つの理由で上振れしている。

**(a) パラメータの過剰最適化**

54通りのグリッドサーチで最良を採用したなら、その最良値には偶然の上振れが
必ず混入する。エッジが完全に0でも、54回引けば最大値は約2.2σ に達する。

**(b) 銘柄ユニバースの結果選抜 ← こちらが桁違いに大きい**

「バックテスト期間の成績が良かった銘柄を残す」だけで、真のエッジが0でも
極めて良好な成績が得られる。東証4000銘柄から116銘柄を「期待値プラス」で
抽出した場合の見かけのエッジ:

```
$ python3 -m ev.cli diagnose --sharpe 0.88 --n-obs 2500 --trials 54 \
      --candidates 4000 --selected 116

選抜だけで生じる見かけの年率リターン: +22.98%
選抜だけで生じる見かけの年率シャープ: +0.724
```

**真のエッジ0で年率+23%が出る。** これは理論値とも一致する。上位α分位の
標準正規の平均は φ(z_α)/α なので、

```
α = 116/4000 = 0.029,  z_α = 1.896,  φ(1.896)/0.029 = 2.30
標本平均の標準誤差 = 0.02/√2500 = 4.0e-4
見かけのエッジ = 2.30 × 4.0e-4 × 252 = +23.2% / 年
```

### 対策

1. **ユニバースを成績で選ばない。** 構造的特徴（時価総額、売買代金、
   カバレッジ数）だけで絞る。これらは事前に観測可能でリターンと独立。
2. **パラメータは学習期間だけで決める。** `walk_forward_grid` は
   「学習期間で最良を選ぶ」方針の正直な期待値を返す。グリッドの最良値ではない。
3. **試した構成数を必ず記録する。** `deflated_sharpe_ratio` に正直な試行数を
   渡す。申告しなければ検定は無意味になる。

### 使える道具

| 関数 | 何を答えるか |
|---|---|
| `selection_inflation` | 銘柄選抜だけで生じる見かけのエッジ |
| `deflated_sharpe_ratio` | 試行数を考慮してもシャープが残るか |
| `probability_of_backtest_overfitting` | パラメータ選択が害になっていないか |
| `multiple_testing_haircut` | シャープを何%減額すべきか |
| `walk_forward_grid` | 最適化を運用した場合の実際の成績 |
| `min_track_record_length` | 有意性到達に必要な観測数 |

## 3. 工程1 — 構造的ユニバース選別

### 考え方

歪みが残るのは「誰も気づいていない場所」ではなく、**気づいていても入れない
場所**である（裁定の限界）。

運用額1000億円のファンドは、意味のあるポジション（運用額の0.5% = 5億円）を
作るために、5億円を数日で建て、数日で処分できる流動性を必要とする。1日の
売買代金が1000万円の会社では物理的にできない。だから割安でも買わない。

この方式では各銘柄について「意味のあるポジションを作れる最大のファンド規模」を
計算する。

```
最大ポジション額 = 売買代金 × 参加率(15%) × 建玉日数(10日)
参加可能な最大ファンド = 最大ポジション額 ÷ 最小ポジション比率(0.5%)
```

売買代金1000万円なら参加可能な最大ファンドは30億円。事実上どの機関も入れない。

### 同時に自分の出口を確保する

優位の源泉である低流動性は、自分にとっての出口リスクでもある。だから
**「彼らには小さすぎるが、自分には十分」** という帯域を探す。

```
自分が建てられる額 = 売買代金 × 自分の参加率(10%) × 処分日数(5日)
建玉余裕度 = 自分が建てられる額 ÷ 目標ポジション額   （1倍以上が必須）
```

資金が増えるとこの帯域から押し出される。個人の優位は資金量に依存する。

### 構造スコア（0〜100）

| 要素 | 配点 | 根拠 |
|---|---|---|
| 機関排除度 | 40 | 参加可能ファンドが小さいほど高い（対数） |
| カバレッジ | 20 | アナリスト0社で満点 |
| 触媒 | 25 | 純現金比率、PBR1倍割れ、親子上場、強制売却 |
| 自分の余裕 | 15 | 出口が確保できているか |

### 触媒として使えるもの

- **純現金 > 時価総額の50%** — 現金だけで時価総額の相当部分を説明できる
- **PBR1倍割れ** — 東証の資本効率改善要請の対象。識別可能な触媒
- **親子上場・持株会社** — SOTPディスカウント
- **強制売却** — 指数除外、12月の税金売り、信用の投げ。ファンダメンタルズと無関係

```bash
python3 -m ev.cli screen --csv universe.csv --portfolio 10000000
```

## 4. 工程2 — ベースレート

### なぜ先に置くのか

「この会社は5年で売上2倍になる」と思ったとき、最初に調べるべきは事業ではなく、
**同じ規模・同じ業種の会社が5年で売上2倍になった歴史的頻度**である。

ベースレートを見ずに個別の物語から確率を組み立てると、確率は例外なく過大に
なる。人間は説得力のある物語を頻度の代わりに使う。

### 経験ベイズによる縮小

バケット別の実現頻度は、標本が小さいと極端に振れる。5戦5勝を100%として扱うと
壊れる。だから全体平均に縮小する。

```
縮小後 = (成功数 + k · 全体率) / (件数 + k)
```

k（事前の強さ）はモーメント法で推定する。バケット間のばらつきが二項ノイズで
説明できる分だけなら k は大きく（強く縮小）、真にばらついているなら小さくなる。

### ベースレートからの乖離チェック

ロジット差はオッズ倍率に等しい。

```
ロジット差 1.0 → オッズ約2.7倍
```

「ベースレート34%に対して62%」はオッズで3.16倍強気という主張である。
そう主張するには理由が必要。`Claim` はロジット差が1.0を超える場合、
`divergence_rationale` の記述を**強制する**（書けなければ記録できない）。

## 5. 工程3 — 事前確約型の予測記録

### 台帳が強制する6つのルール

1. **確率は0でも1でもない**（0.02〜0.98）。確実は存在しない
2. **各主張に期限と判定方法が必須。** 「いつ・何を見れば外れたと分かるか」
3. **期限は記録時点より未来。** 後から日付を遡って書けない
4. **ベースレートから大きく離れるには根拠の記述が必須**
5. **シナリオ確率の合計は1**
6. **記録は追記専用。解決も追記。上書きは物理的に不可能**

### 改変不能性の二重防御

自分の予測を後から書き換えられる記録は、記録として無価値である。
「あのときこう思っていた」は必ず結果に都合よく歪む。

1. **SQLiteのトリガー**が `UPDATE` / `DELETE` を物理的に拒否する
2. **ハッシュチェーン**が各行に直前行のハッシュを含む。DBファイルを直接
   編集しても `verify()` が検出する

```python
>>> conn.execute("DROP TRIGGER entries_no_update")   # トリガーを外しても
>>> conn.execute("UPDATE entries SET payload = ...")  # 書き換えても
>>> ledger.verify()
(False, 'seq=1: hash 不一致（記録=a3f2…, 期待=91bc…）。payload が改変された可能性があります。')
```

### 良い主張と悪い主張

| | 例 |
|---|---|
| 良い | 「2027年3月期の営業利益が会社予想の120億円を上回る」<br>期限 2027-05-15、判定 決算短信の営業利益 |
| 悪い | 「この会社は成長性がある」<br>→ 判定できない = 記録する価値がない |

### 期限超過の未解決を可視化する

**都合の悪い予測を放置するのが、最も一般的な自己欺瞞の形である。**
`overdue_claims()` はそれを明示的に取り出す。ここが溜まっていると
キャリブレーションは測れない。

## 6. 工程4 — キャリブレーション

### Murphy分解

```
Brier = 信頼度(REL) − 解像度(RES) + 不確実性(UNC)
```

| 項 | 意味 | 方向 |
|---|---|---|
| 信頼度 REL | 確率のズレ | 低いほど良い |
| 解像度 RES | 事象を区別できているか | 高いほど良い |
| 不確実性 UNC | 事象固有の難しさ | 自分では変えられない |

**重要**: 解像度が0でも信頼度は完璧になりうる。「常にベースレートを答える」は
完全に較正されているが役に立たない。だから両方を同時に見る指標を使う。

```
Brier Skill Score (BSS) = 1 − Brier / UNC
```

BSS ≤ 0 なら「常にベースレートと言う」に負けている。個別の見立てが
価値を生んでいない。

### 較正傾き

`outcome ~ logistic(b₀ + b₁ · logit(p))` を当てはめる。

| 傾き | 意味 | 対策 |
|---|---|---|
| b₁ < 1 | 自信過剰（確率が極端すぎる） | 中央に寄せる |
| b₁ = 1 | 適正 | — |
| b₁ > 1 | 自信不足 | 外側に伸ばす |

`recalibrate()` は実測の傾きと切片で将来の確率を補正する。
**より良い予測をする必要はない。既存の予測の目盛りを直すだけで期待値が改善する。**
これは無料の改善である。

## 7. 工程5 — サイジング

### なぜここが最重要か

```
勝てば +50%、負ければ −40%、確率は50/50

  算術期待値              = +5.00%       ← 一見おいしい
  毎回全額投入時の成長率  = −5.13% / 回  ← 100回で無一文
  毎回25%投入時の成長率   = +0.62% / 回  ← 増える
```

**同じ賭けでも賭け金だけで符号が反転する。** 算術期待値がプラスであることは
儲かることを意味しない。

### 処理順

```
1. シナリオ分布から厳密なケリー比率を数値解で求める
     Σ p·ln(1 + f·r) を直接最大化する。正規近似 μ/σ² は裾が厚い分布で
     過大なサイズを出すため使わない
        ↓
2. エッジ推定値をベイズ縮小する
     τ = 情報レシオ(0.25) × σ,   s = 0.5 × σ
     w = τ²/(τ² + s²) = 0.20     ← 既定では主張エッジを2割に値引き
     事前分布は必ず σ に比例させる。絶対値（「年率3%」等）で与えると
     保有期間やボラティリティが変わったときに単位が壊れる
        ↓
3. 分数ケリー（既定0.25倍）でモデルリスクを織り込む
        ↓
4. 実測キャリブレーションでゲートする  ← 本方式の中核
        ↓
5. キャップを適用する
     1銘柄上限 / 最悪シナリオ損失上限 / 流動性(出口)
        ↓
6. どの制約が効いたかを明示して返す
```

### 4のゲートが中核である理由

「自分にエッジがある」という主張は、**実測されたキャリブレーションによって
裏付けられるまで、サイジングに反映されない。** スキルが証明されていない
状態でのサテライト配分は0になる。

ゲートが開く条件は3つ全て。

1. 解決済み予測が20件以上
2. BSS > 0
3. BSSの95%信頼区間の下限 > 0（偶然では説明できない）

デモでの遷移:

```
  10件: 倍率 0.00  — サンプル不足
  20件: 倍率 0.00  — BSS=0.128 だが信頼区間が0を含む。まだ運と区別できない
  40件: 倍率 1.00  — BSS=0.399 / 基準0.15
 150件: 倍率 1.00  — BSS=0.301 / 基準0.15
```

### なぜフルケリーを使わないのか

フルケリーの c 倍を賭けるとき、残高が最高値の a 倍まで下落する確率は

```
P(a) = a^(2/c − 1)
```

| ケリー倍率 c | 半減確率 |
|---|---|
| 1.00（フル） | **50.0%** |
| 0.50 | 12.5% |
| 0.25 | 0.78% |
| 2.00 | 100%（成長率0） |

フルケリーは成長率が最大だが、半減確率がちょうど50%になる。実務では使えない。

### コア・サテライトは妥協案ではない

自分のアルファ推定値**自体に**大きな推定誤差があるとき、期待値最大化の解が
この形になる。サテライトが全部外れてもコアの市場リターンは残る。

## 8. 使い方

### 依存パッケージ

**なし。** Python 3.9以上の標準ライブラリのみで動く。
`pip install` は不要。numpy も pandas も使わない。

### コマンド

```bash
# 全工程を合成データで実行（まずこれを見る）
python3 -m ev.cli demo

# 既存バックテストの診断
python3 -m ev.cli diagnose --sharpe 0.88 --n-obs 2500 --trials 54 \
    --candidates 4000 --selected 116

# サイジングの直観
python3 -m ev.cli bet --win 0.5 --loss -0.4 --p 0.5

# アルファ検証に必要な年数
python3 -m ev.cli years --alpha 0.03 --te 0.15

# 構造的ユニバース選別
python3 -m ev.cli screen --csv universe.csv --portfolio 10000000

# 予測の登録 → 結果の記録 → キャリブレーション評価 → サイジング

python3 -m ev.cli resolve     --journal j.db --id FC00001 --claim c1 --outcome true
python3 -m ev.cli journal     --journal j.db
python3 -m ev.cli calibration --journal j.db
python3 -m ev.cli size        --journal j.db --id FC00002 --adv 10000000
```

`examples/forecast_example.json` を参照。


## 9. この方式が保証しないこと

- **儲かることを保証しない。** 保証するのは「自分を騙さないこと」だけである
- 構造的に大口が入れない領域を選んでも、そこに歪みがあるとは限らない。
  流動性が低いこと自体がリスクの対価である可能性は常に残る
- キャリブレーションが良いことは、リターンが良いことを意味しない。
  確率が当たっても、賭け金と対象を間違えれば損をする
- ベースレートは過去の頻度であり、将来の頻度ではない
- 選抜バイアスの推定はモンテカルロであり、真のリターン分布が正規から
  大きく外れる場合は過小評価になる

**この方式の価値は、期待値を上げることではなく、期待値を上げたと
思い込む経路を塞ぐことにある。**
